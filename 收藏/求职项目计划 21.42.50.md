## 一、先记住一句话

**你手上五个候选项目里，有三个是培训班课程项目（外卖、黑马点评、天机学堂）。
简历上最多只能出现一个，而且必须是改造过的。**

原因：这三个是全网最泛滥的教程项目，面试官一年看几百份。写上去等于告诉对方
"我跟着视频敲完了"。但它们作为**学习载体**是好东西 —— 里面的技术点（Redis 缓存三兄弟、
分布式锁、秒杀、微服务拆分）全是面试必问，学了不亏。

所以正确姿势是：

```
课程项目  →  学技术（不写进简历）
                ↓ 把学到的技术
自研项目  →  用上去 + 压出数字（写进简历）
```

黑马点评教你 Redis 秒杀，你就把那套超卖控制用到外卖的下单接口上，压测出 QPS 提升；
天机学堂教你微服务拆分，你就把外卖拆成服务 + 上 K8s。**这才是你的东西。**

## 三、五个项目的取舍

| 项目 | 决定 | 定位 | 理由 |
|---|---|---|---|
| 容器化动态靶场 | **保留 + 升级** | 一号主力 | 多租户隔离、动态调度、生命周期回收，正好是 2026 年 AI Agent 沙箱要解决的问题 |
| 苍穹外卖 | **做，但必须改造** | 二号 | 技术最全、链路最完整，学习价值最高；原样照抄 = 学生作业 |
| 黑马点评 | **只学不写简历** | 技术模块 | Redis 实战最好的教材，但项目本身没区分度 |
| 天机学堂 | **选学，优先级最低** | 技术模块 | 微服务全家桶，但摊子大、周期长，容易烂尾 |
| 多人协作编辑器 | **保留 + 换算法** | 三号 | 并发编辑冲突合并是硬难点，讲清楚就是加分项 |
| 实验室/环境运维 | **降级为配套** | 底座 | 单独吹是"我搭了很多东西"，缺主线；当上面项目的运行环境才成闭环 |

### 三条原则

1. **技术多 ≠ 简历强。** 课程给的"完整"不是你做的完整，表结构、接口、模块边界都是别人设计的。
2. **区分度来自「课程之外的决策」+「可量化的结果」。**
3. **每个简历项目至少要有一个数字**（QPS、延迟、并发数、资源占用）。面试官只信数字。

## 六、黑马点评（学 Redis，产出收割进外卖）

**定位：技术学习模块，不写进简历。** 它的价值是 Redis 面试题全覆盖。

**关键：不要从头到尾敲一遍。** 这门课真正值钱的只有下面这几块，挑着做，预计 1～2 周：

| 模块 | 学到的技术 | 面试问不问 | 收割到哪 |
|---|---|---|---|
| 短信登录 | Redis 存 session、token 刷新 | 常问 | 外卖的 JWT 可以对比讲 |
| 商户查询缓存 | **缓存穿透（空值/布隆）、击穿（互斥锁/逻辑过期）、雪崩** | **必问** | 外卖菜品查询接口 |
| 优惠券秒杀 | **全局唯一 ID、乐观锁、悲观锁、Redisson 分布式锁、Lua 脚本原子性、Redis Stream 异步下单** | **必问** | **外卖订单超卖控制** |
| 达人探店点赞排行 | SortedSet | 偶尔 | 外卖 day11 销量 Top10 可以用 |
| 好友关注共同关注 | Set 求交集 | 少 | 跳过 |
| 附近商户 | GEO | 少 | 跳过（但外卖配送范围能用） |
| 用户签到 | BitMap | 偶尔 | 跳过 |
| UV 统计 | HyperLogLog | 偶尔 | 跳过 |

**必做的只有两块：商户查询缓存 + 优惠券秒杀。** 这两块是外卖阶段二第 3 条的弹药，
学完直接搬到外卖上压测出数字，一份功夫两处用。其余模块知道是什么、什么场景用就够了。

⚠️ 这门课**不要建独立仓库长期维护**，学完就归档。你的简历上不需要它。

## 七、天机学堂（选学，优先级最低）

**定位：微服务技术模块。有余力再做，没余力直接跳过。**

覆盖的技术：SpringCloud、Nacos 注册/配置中心、OpenFeign、Gateway、Sentinel 限流熔断、
Seata 分布式事务、RabbitMQ、Caffeine + Redis 多级缓存、XXL-JOB 分片定时任务、
积分排行榜（Redis + 定时任务分片）。

**为什么优先级最低（三个理由）：**

1. **摊子太大。** 要同时起 Nacos、MySQL、Redis、RabbitMQ、Sentinel、XXL-JOB 六七个中间件，
   环境问题会吃掉你大半时间，学到的技术却未必更多。你 3～4 小时/天，很容易烂尾。
2. **性价比低于"自己拆一次"。** 跟着课程拆好的服务敲一遍，和自己把外卖从单体拆成
   3 个服务（用户/订单/商品）+ 上 K8s，后者面试能讲的东西多得多 —— 因为拆分边界是你定的，
   会被追问"为什么这么拆""事务怎么办"，那是真本事。
3. **微服务在 2026 年不是加分项，是常识项。** 会用 Nacos + Feign 不加分，
   讲得清"为什么要拆"和"拆了之后一致性怎么保证"才加分。

**所以建议的替代路线**：跳过课程，直接在外卖上做一次真实拆分（阶段二第 4 条的延伸）。
真想系统学微服务，就只看天机学堂里**分布式事务**和**多级缓存**两章，其余不碰。

## 八、Agent 评测沙箱 / 动态靶场（一号主力）

路径：`/Users/luoshuangshuang/Downloads/ctf-range`

这几个问题和 AI Agent 代码执行沙箱要解决的是同一批。改个定位，故事完全不同。

- [x] **第 0 关：理解容器**（已完成）

- [ ] **第 2 关**：制作带真漏洞的靶机镜像，flag 由环境变量注入

- [ ] **第 3 关**：用户会话 + flag 归属校验 + 提交频率限制 → 这就是"答案风控防作弊"
- [ ] **第 4 关**：容器生命周期管理，超时自动回收

⚠️ 本机有其他在跑的 bench 容器（`physics-*`、`biology_*`），
清理时**禁止** `docker rm -f $(docker ps -aq)` 之类的全量删除，只删自己项目的。
