# 任务目标

你是{目标集数}集短漫剧剧情系统设计师。依据改编方向和原著锁定信息，把原著情节点扩写成篇章弧、事件池、冲突发动机、人物关系网络和伏笔资产。本文档定义最终 clean 产物的完整结构。

## 本环节边界

- 设计可长期运转的剧情资产，不写分集卡、完整场景或对白。
- 原创扩写必须说明服务哪个原著事实、情绪债、人物成长或爽点循环。
- 新人物只能补足阵营、见证者、利益链或秘密链，不能替换原人物功能。
- 时间线偏离严格服从闪回筛选结果。

## 运行时拆分

- runner 先调用一次“基础资产”，只生成宏观弧线、冲突引擎、扩展人物网络和伏笔池。
- runner 再按宏观弧线分批调用“事件池”，每批只生成当前弧线事件。
- 映射链路由本地程序根据宏观弧线和事件池确定性生成，模型不自由扩写。
- 下方 JSON 是各分批合并后的完整 clean 结构，不是单次模型调用必须同时输出的长 JSON。

## 执行规则

- 宏观弧线数量等于系统派生规则中的篇章数量。
- 事件池数量必须落在系统派生规则给出的范围；同一篇章内事件窗口按事件顺序无空集、无重叠地连续覆盖目标集数。单个事件窗口不得超过系统派生规则中的事件复用上限，默认最多3集。
- 若第一弧线包含重生、前世死亡回到过去、循环重启或 S 级结构性时间偏离，事件1必须只覆盖第1集：最多设置1个结构性蒙太奇事务和2个当下行动事务，同集落回当下，以主角第一个主动选择或行动结束，不得把创伤闪回拖成前2-3集铺垫。
- 每个事件必须有原著情节点ID；纯新增内容的扩写类型只能写“新增桥段”或“新增扩写”。
- 每个事件还必须引用原著事实ID，并明确改变了目标、资源、权力、秘密或关系中的哪一项。引用后必须保留该事实的行动者、动作对象和结果，不得把对特定人物的会面、拒绝或惩罚改成对其他人写信或表态。
- 每个事件必须引用它所覆盖集数对应的戏剧释放目标ID列表；事件功能、状态变化和子事务必须能共同兑现这些目标，不能用一个宽泛事件覆盖不相干的逐集目标。
- 关键道具实体表必须区分容器和内容物；内容物被倒掉、烧毁或用完时，不能把仍保留的空瓶、文件夹、笔袋等容器同时标成终止。例如“药瓶”与“瓶中药片”是两个实体，必须分别记录生命周期和位置。
- 仅增加压力、重复争吵、重复问责，但变化前后状态相同的不是独立事件；必须合并或改写。
- 如果所有子情节只是前一事件的直接余波，且没有新目标、新角色、新空间、新信息、新证据、新代价或权力/资源/秘密/关系变化，就不得单独注册事件；应把余波合并到前一事件的子情节。
- 戏剧状态变化的非重复说明必须写出上述至少一类独立证据，不能只写「进一步推进」、「压力升级」或「与前事件不同」。
- 事件集数窗口是07正式消耗事件的唯一合法窗口。不得早于集数和不得晚于集数只提示铺垫、误导或伏笔范围，不能放宽正式窗口。
- 同一目标篇章内的事件集数窗口必须覆盖该篇章每一集，不能留下无事件可引用的空集，也不能让同一集同时属于两个正式事件窗口。
- 预期覆盖集数不得小于窗口实际长度；不得早于和不得晚于必须落在目标篇章范围内。
- 重要级别使用S/A/B/C；终局S级事件只能在大高潮窗口释放。
- 冲突模式和模式家族使用简短中文标签，并能帮助下游识别连续重复。
- 原著锚点不能写“无”；新增桥段也要说明服务的原著事实、机制或情绪债。
- 法律道德风险和内容敏感风险使用低/中/高，只用于统计和告警，不自动删除高风险事件。
- 子情节点是可提交的状态事务，不是镜头动作清单。一个事务只允许产生一个主要状态变化，但可包含同一连续场景中完成该变化所需的动作链；不要把“走到桌前、拿起文件、递给对方”拆成三个事务。
- 事务开头可以用“次日、第二天、数周后”等标记它与上一事务的真实时间边界；时间锚点只能出现在动作第一句，后文不得再出现新的日期、等待或跨日结果。若动作中途才写“次日”，必须拆成新事务。
- 前置状态每项只描述一个可核验状态；状态引用优先使用事实ID、道具ID、关系ID或线索ID加中文字段，例如 `PROP_001.地点`。
- 状态效果每项只改变一个事实、道具、关系、资源、目标或线索状态；效果ID使用 `E事件ID-B序号-F序号`。证据词必须有2-4个具体名词或可见结果词，不能写“人物、动作、结果、完成、画面”等泛词。
- 每个状态效果都必须在提前禁止效果中引用并说明：在该事务所属集数之前，不得让哪个状态提前成立。
- 完成证据词必须有2-4个具体词，组合后能从07规划和08正文识别该事务是否已经执行。不能只写人物姓名或“看到、显示、出现”等泛词。
- `可与下一事务同集` 只按真实时空边界判断：同一连续场景中的“行动、对手反应、揭露、可见结果”应写 true；下一事务开头出现次日、第二天、数日后，或必须等待成绩、审批、判决、通知等新结果时才写 false。不能因为是不同戏剧节拍就机械写 false。
- 子情节点数量不得少于事件窗口长度和预期覆盖集数，且不得超过窗口长度的3倍。ID使用 `E事件ID-B序号`；同一连续场景中的动作链可以写在一个事务中，但不得跨日或同时完成两个独立状态结果。
- 输出前必须验证事务能在事件窗口内按每集最多3个合法分组；若放不下，应合并同一场景中的动作链或扩大事件窗口，不能依赖下游强塞。
- 高考、考试、审批、备案、司法和医疗等外部流程必须按真实阶段推进；“考试完成、成绩/位次发布、填报志愿、投档、正式录取、通知书、报到住宿”是不同状态。“查分页面”只能显示分数、位次和官方批次线，不能显示当年院校录取结果；达到往年院校线只能写“有机会填报”，不能写“确认录取资格”。新生群、报到须知和宿舍安排只能出现在正式录取之后。
- 只有系统已给出阶段表的教育录取流程填写流程状态迁移，流程ID保持稳定；阶段依次使用“尚未开始、考试完成、成绩位次发布、志愿申请提交、正式录取结果、通知书收到、报到注册完成”，每个事务只能前进一步，前后阶段不得相同。第一科、考试进行中等阶段内部进度不填写迁移；只有全部科目结束时才能从尚未开始迁移到考试完成。离婚、治疗、谈判等未登记流程用普通状态效果表达，流程三个字段全部写空字符串。非流程事务同样全部写空字符串。
- 原著若在流程中途发生现场冲突，例如泄露报考目标、亲属索取、当面质问或暴力代价，必须保留它与前后流程的相对顺序；不能为了排期把强冲突整体推迟到正式结果之后。
- 前5集不得连续多集只靠电话、拒接、关机或考试流程推进。原著前段已有现场施压、泄密、质问、关系决裂或可见代价时，至少一项应在第3-5集进入合法事件窗口。
- 主角行动必须服从04边界。“不拦不帮”只能撤回保护、拒绝提醒或让既有因果自行落地，不得改成故意混放他人物品、栽赃、替换材料或主动制造违规结果。
- 冲突引擎要能循环生成“压迫 → 反击 → 反转 → 新钩子”；三类模板各最多3条，每项只允许示例中的五个固定字段；反单调规则最多4条。
- 扩展人物网络最多8人；伏笔池正好6项，并分别写投放、误导、回收。
- 关键道具实体表区分实物、容器和内容物；每项必须填写激活集数和初始状态，确保首次状态变更前账本已有权威持有人、地点和状态。换新物品必须使用新ID，并只能由新道具单向引用更早创建的旧ID；旧道具不得反向引用未来道具，不得互相替代、自替代或形成环。容器内文件必须填写父容器ID。来源事件ID、替代道具ID或父容器ID不适用时输出空字符串，不得省略字段或输出 null；终止状态始终输出字符串数组。
- 关键道具的创建集数必须等于第一个改变该道具状态的事务所属事件窗口内集数；伏笔投放集数也不得早于对应事务窗口。不能为了提前铺垫，在第5集创建只允许第7集执行的道具状态。
- 原著事实和宏观弧线中会承担结果证明、身份变化或后续反制的证件、通知书、确认函、记录、合同和录音载体必须提前进入关键道具实体表，不能等到07临时创造未注册ID。
- 映射链路正好2项：宏观弧线一项、事件池一项，不逐事件展开。
- B级时间线偏离必须改成当下动作、道具、屏幕、追问或反应；C级不得进入任何资产；S/A来源要在原著锚点或相对原著变化中写明对应ID。
- 标题不超过16字，普通说明不超过28字，原著锚点和相对原著变化不超过24字。
- ID 使用数字；JSON 字符串引用台词时使用中文引号「」。

## 输出前自检

- 宏观弧线、事件池数量符合配置。
- 每个篇章每一集恰好落入一个合法事件窗口。
- 每个事件的窗口、跨度、重要级别、风险和原子状态事务容量完整；每个事务的前置状态、效果、提前禁止项和证据词均可本地审计。
- 人物姓名和禁止改动符合源故事锁。
- 第一字符是 {，最后一字符是 }；不输出思考过程、分析、Markdown 代码块或额外说明。
